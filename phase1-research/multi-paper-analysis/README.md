# 多论文综合分析系统

## 背景

单篇论文信噪比较低，需要将多篇论文放在一起进行跨论文综合分析。

---

## 设计思路

### 方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A. 长上下文直灌** | 全部论文喂给长上下文模型（如 Gemini 100万 token） | 简单粗暴，模型自己找关联 | 成本高，容易"迷路"，难追溯 |
| **B. 分层摘要+综合** | 先结构化摘要每篇，再主题聚类+矛盾检测 | 可控、可追溯、成本低 | 可能丢失细节 |
| **C. 知识图谱+RAG** | 提取三元组构建知识图谱，查询时检索+生成 | 结构化、可查询、可视化 | 实现复杂，三元组提取有噪声 |

**选择**：方案 B 为主，按需深挖

---

### 处理流程

```
阶段1: 结构化提取（每篇论文）
├── 研究问题
├── 数据来源
├── 核心方法
├── 主要结论（3-5条）
├── 局限性
└── 特色亮点

阶段2: 跨论文分析
├── 共识检测（多篇论文都同意的结论）
├── 矛盾检测（不同论文的冲突点）
├── 方法对比（谁用了什么方法，效果如何）
├── 时间线（领域发展脉络）
└── 空白识别（还没人做的方向）

阶段3: 交互式查询
└── 用户提问 → 检索相关段落 → 综合回答+引用来源
```

## 工具选型

### PDF → 结构化文本

| 工具 | Stars | 特点 | 链接 |
|------|-------|------|------|
| **MinerU** | 53.8k | 专为 AI4S 设计，支持复杂布局、表格、公式 | [GitHub](https://github.com/opendatalab/MinerU) |
| **Marker** | 31.5k | 速度快、精度高，基于 Surya OCR | [GitHub](https://github.com/datalab-to/marker) |
| **GROBID** | 4.6k | 学术论文专用，提取结构化元数据 | [GitHub](https://github.com/grobidOrg/grobid) |

**推荐**：MinerU（标签含 `ai4science`，高度契合）
